# 출장 조율사용 업무 도구: MVP 스펙

한국의 출장(방문) 피아노 조율사를 위한 고객/악기 이력, 재방문 알림, 예약 페이지 도구.
개인 포트폴리오 프로젝트이며 수익 목표는 없습니다.

## 핵심 가설 (미검증)
조율사의 수입은 같은 고객이 매년 다시 부르는 데서 나온다. 따라서 **재방문 유도(리텐션)** 에 집중한다.
실제 조율사에게 검증된 것은 없다.

## MVP 범위
**포함**: (1) 고객·악기 관리 (2) 시술 기록 (3) 재방문 알림 초안 (4) 예약 페이지 (5) 오늘 일정과 지도 앱 딥링크
**제외(나중)**: 경로 최적화, 세금계산서/현금영수증 연동, 결제, 중개/리뷰/검색 노출, 다중 조율사 팀 계정

## 핵심 흐름
고객·악기 등록 → 방문 후 시술 기록, 다음 권장일 제안(기본 6~12개월, 수정 가능) → 2~4주 전 알림 초안이 인박스에 생성 → 조율사 확인 후 예약 링크가 담긴 메시지 전달 → 고객이 시간 선택 → 조율사 수락 → 일정에 등록

## 개발 단계
1. 고객/악기/시술 기록 CRUD + 로그인. 완료 기준: 가짜 데이터 약 30건 입력·조회 **(진행 중)**
2. 다음 권장일 계산, 재방문 인박스, 메시지 초안
3. 가능 시간 설정, 고객 예약 페이지, 수락 흐름
4. 오늘 일정, 지도 딥링크, PWA
5. (선택) SMS 연동, 다듬기, 문서화

## 설계 결정
- 웹/PWA 우선: 설치 부담이 적고 고객은 링크만 있으면 된다.
- 고객 계정 없음: 링크만으로 동작해야 재예약 전환율이 높다.
- 조율사가 확인한 뒤에만 알림 발송.
- 결제/세금계산서 제외: 규제·연동 비용이 크고 핵심 가설과 무관.
- 지도는 딥링크만.

## 보안 요구사항
다루는 데이터는 이름, 연락처, 주소, 설치 장소, 방문 이력으로 개인정보(PIPA 적용).
- 조율사별 DB 행 단위 격리 (RLS, `tests/rls.test.ts`로 검증)
- 인증은 검증된 서비스(Supabase Auth 이메일 링크) 사용, 비밀번호를 직접 저장하지 않음
- 고객용 링크: 추측 불가능한 단일 목적 토큰, 만료, 요청 제한, 해당 고객 정보만 노출
- 최소 수집: 주소는 필요할 때만 입력
- 연락 동의 기록, 고객 삭제 시 이력도 함께 삭제
- HTTPS 강제, 저장 시 암호화(관리형 DB 기본), 정기 백업
- 시크릿은 환경변수로만, 코드에 넣지 않음
- 로그에 개인정보 금지, 분석/추적 스크립트 금지

## 위험
- 모든 가설이 실제 조율사로 검증되지 않았다 (포트폴리오에도 그대로 밝힐 것)
- 조율사 수가 적다 (협회 등록 약 600명 이상, 비회원 규모 불명)
- 전화, 수첩, 카카오톡, 무료 예약 도구로 충분하다고 느낄 수 있다
- 카카오 알림톡 자동 발송은 사업자 요건으로 막힐 수 있다 (확인 필요)
