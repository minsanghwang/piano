# 중간 점검 1차 제출 초안 (2026-11-05 기준)

> 아래는 사실 기반 초안입니다. 본인 말로 고쳐 쓰세요. 특히 "AI에게 맡긴 일과 내가 판단한 일"은 본인이 직접 써야 합니다.

## 이번에 만든 것
출장 피아노 조율사를 위한 웹앱(Next.js + Supabase, Vercel 배포).
- 이메일+비밀번호 회원가입·로그인·로그아웃, 비밀번호 재설정/변경, 회원 탈퇴(데이터 전체 삭제)
- 고객·악기·시술 기록의 추가·수정·삭제, 다음 조율일 자동 계산
- 재방문 안내 메시지 초안(복사/공유), 가능 시간 설정, 로그인 없이 쓰는 고객 예약 링크, 예약 수락/거절, 오늘 일정과 지도 링크
- 조율사별 데이터가 DB 수준에서 격리됨(타인 데이터 읽기·수정·연결 모두 차단), 휴대폰 화면 대응

## 확인하는 방법 (3단계)
1. https://piano-sang-e.vercel.app 에서 회원가입 후(메일 확인 필요 시 링크 클릭) 로그인한다.
2. 설정에서 가능 시간을 추가하고, 고객 → 악기 → 방문 기록을 입력한다. 재방문 탭에 안내 초안이 뜨는지 본다.
3. 설정의 예약 링크를 시크릿 창(또는 휴대폰)에서 열어 예약하고, 예약 탭에서 수락한 뒤 오늘 탭에서 확인한다.

## 바뀐 점과 그 이유
- 중개 앱 → 조율사 업무 도구: 사용 빈도가 낮고 우회가 쉬워서.
- 악기는 피아노만: 수요가 작고 검증되지 않은 악기를 넣을 근거가 없어서.
- 알림은 자동 발송 대신 초안+복사: 카카오 알림톡이 사업자 요건을 요구할 수 있어서.
- 이메일 링크 로그인만 있던 것을 비밀번호 로그인으로 확장: 링크 메일은 발송 횟수 제한에 자주 걸림.
- 테스트로 찾아 고친 버그: 예약 수락 버튼 미동작, 오류 문구 오표시, 저장마다 화면이 비는 현상 등.

## AI에게 맡긴 일과 내가 판단한 일 (직접 작성)
- 사실 메모: 코드·DB 설계·테스트·문서 작성은 AI(Claude)가 진행했고, 프로젝트 주제와 방향 전환, 범위 제한, 기술 스택 선택, 알림 방식, 인터뷰 대신 어머니께 비공식으로 묻기, 배포·테스트 계정 삭제 승인 등은 본인이 결정함.
- 본인이 직접 해 본 것(이메일 링크 로그인, 화면 사용 후 피드백 등)을 구체적으로 적으면 좋음.
