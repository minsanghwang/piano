# 계획서: 출장 조율사용 업무 도구 (조율 노트)

작성: 2026-11-05 (v1) · 상세 스펙은 [spec.md](spec.md), 결정/변경 기록은 [changelog.md](changelog.md)

## 1. 목표
- **한 줄 소개**: 출장 피아노 조율사가 고객·악기 이력을 기록하고, 재방문 시기를 놓치지 않게 안내하고, 고객이 링크로 예약할 수 있게 하는 웹앱
- **대상**: 혼자 방문 조율을 하는 피아노 조율사 (고객은 계정 없이 링크만 사용)
- **핵심 기능 3가지**: (1) 고객·악기·시술 기록 (2) 다음 조율일 계산과 재방문 안내 메시지 초안 (3) 예약 링크와 오늘 일정
- **완성의 기준**: 조율사가 가짜 고객 30명을 입력해 조회하고, 고객이 링크로 예약하면 조율사가 수락해 일정에서 확인할 수 있다. 실제 조율사에게 써 보게 하는 것은 이 과정 범위 밖이다.

## 2. 문제 정의와 방향 전환 이력
1. 급한 공장 부품 조달 앱: 사용 빈도가 낮고 양면 시장이며, 호환 오류에 대한 책임 부담이 있고 현장 지식이 없어 보류.
2. 못난이 농산물 유통: 물류 사업이라 개발이 강점이 되지 않아 후순위.
3. 피아노 조율 중개 앱: 사용 빈도 낮음, 건당 금액 작음, 우회 쉬움, 조율사 수 적음으로 포기.
4. **조율사가 매일 쓰는 업무 도구**로 전환 (현재 프로젝트). 중개가 아니라 도구이므로 사용 빈도가 높다는 가설.

**핵심 가설(미검증)**: 조율사 수입은 같은 고객이 매년 다시 부르는 데서 나오므로 재방문 유도가 가장 중요하다. 실제 조율사로 검증하지 않았다.

## 3. 범위
- 포함: 고객/악기/시술 기록, 재방문 안내 초안, 예약 페이지와 수락, 오늘 일정과 지도 링크
- 제외: 경로 최적화, 결제, 세금계산서, 중개·리뷰, 다중 조율사 팀 계정, 피아노 외 악기, 자동 문자/카카오 발송
- 보안: 조율사별 데이터 격리(DB 행 단위), 직접 만들지 않은 인증, 고객 링크는 추측 불가능한 토큰과 요청 제한

## 4. 기술
Next.js(App Router) + Supabase(Auth, Postgres, RLS), Vercel 배포 예정. 선택 이유는 행 단위 격리와 로그인을 직접 구현하지 않고 해결할 수 있기 때문.

## 5. 진행 계획과 점검 방법
| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 1 | 고객/악기/시술 CRUD + 로그인 | 가짜 데이터 30건 입력·조회 |
| 2 | 다음 권장일, 재방문 인박스, 메시지 초안 | 단위 테스트 + 화면 확인 |
| 3 | 가능 시간, 고객 예약 페이지, 수락 | DB 테스트(이중 예약, 격리) + 브라우저 E2E |
| 4 | 오늘 일정, 지도 링크, PWA | E2E |
| 5 | 배포, 오류 표시 개선, (선택) 문자 연동 | 배포 주소에서 직접 확인 |

## 6. 알려진 위험
- 모든 가설이 실제 조율사로 검증되지 않았다.
- 조율사 수가 적다(협회 등록 약 600명 이상, 비회원 규모 불명).
- 조율사가 전화·수첩·카카오톡으로 충분하다고 느낄 수 있다.
- 카카오 알림톡 자동 발송은 사업자 요건으로 막힐 수 있다(확인 필요).
- 예약 슬롯 길이(2시간) 등 일부 기본값은 임의로 정했다.
